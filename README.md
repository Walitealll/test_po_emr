# BLE-график ЭМГ и угла с управлением измерениями

## Запуск

Дважды щёлкните `start_ble_protocol.cmd`. Приложение само подключается к
`E104-BT5032A`, подписывается на FFF1 и находит FFF2 для команд. Затем
нажмите **START измерения**. Автоматический START не отправляется, в том
числе после переподключения. Кнопка **STOP измерения** посылает остановку.

Системный Bluetooth должен быть включён. Если устройство допускает только
одно соединение, закройте другие подключённые к нему приложения. Старая
версия `start_ble_adc.cmd` работает с другим форматом и для этого протокола
не подходит. Предыдущие программы COM5/COM9/BLE не изменены.

Для запуска нужны `plot_ble_protocol.py` и `device_protocol.py` рядом с CMD.
Окружение `.venv_ble_adc` и уже установленные Bleak/Matplotlib переиспользуются.
При переносе на другой ПК файл запуска создаёт окружение и устанавливает
зависимости; для первой установки нужен интернет и Python 3.

## Формат

Все многобайтовые числа **little-endian**. Никаких ASCII HEX/пробелов.

| Тип | Длина кадра | Назначение |
| --- | --- | --- |
| `01` | 4 байта | Напряжение uint16 в мВ и код зарядки |
| `02` | 3 байта | Событие устройства и код ошибки |
| `03` | 47 байт | 20 uint16 ЭМГ, uint16 угла, uint32 времени |
| `04` | 2 байта | Команда: `04 01` START, `04 02` STOP |

Измерения: 20 ЭМГ-отсчётов с шагом **0,5 мс**, то есть 2 кГц.
Кадр номинально каждые 10 мс (100 Гц). Угол делится на 10: 1800 → 180°.
Метка времени — конец окна/момент последнего ЭМГ-отсчёта и угла.
Первый ЭМГ-отсчёт: `timestamp_ms - 9.5`; последний: `timestamp_ms`.
Время на START не обнуляется. Метка источника имеет сетку 5 мс; соседние
кадры обычно отличаются на 10 мс. Поддержано переполнение uint32.

Графики имеют общее скользящее окно **ровно 5 секунд**. Во время приёма
положение отсчётов задают метки платы, а не скорость доставки Notify.
Когда данных нет, правый край продолжает двигаться по часам ПК; значения
не экстраполируются. Паузы/пропуски окон не соединяются линией. Отсчёты
с дублирующей/обратной меткой не рисуются, выдаётся предупреждение.
При перезагрузке устройства переподключитесь для начала новой шкалы.
Новая BLE-сессия сбрасывает локальный буфер, но START не обнуляет метки.

Notify может содержать несколько кадров, часть кадра или смесь типов.
Неполный кадр сохраняется, неизвестный тип пропускается по одному байту,
как в `frame_parser.py` репозитория. Преамбулы и CRC в протоколе нет:
после потери/вставки байта гарантировать синхронизацию и целостность нельзя.
Неизвестные байты, остаток буфера и разрывы времени отображаются в окне.

## Питание и события

Зарядка **по protocol.md и уточнению пользователя**:

- `0`: кабель отключён;
- `1`: кабель подключён, заряд идёт;
- `2`: кабель подключён, заряд окончен.

Показываются вольты, милливольты, сырой код и возраст телеметрии. Процент
заряда не вычисляется: его нет в протоколе и не задана модель аккумулятора.
Телеметрию питания плата посылает раз в 10 с; её отсутствие сразу после
подключения не считается ошибкой. Если статус ещё неизвестен, START можно
попробовать: окончательно запрет кабеля проверяет сама плата.

События `02`: `1` — кабель вставлен, `2` — низкий заряд,
`3` — измерения остановлены. Для события 3 ошибки `1`/`2` показываются как
ошибка BNO055/таймаут I2C. Код `0` — нормальная остановка.
После события кабеля START блокируется до кадра питания с зарядкой `0`.
После низкого заряда START блокируется до нового соединения; порог снятия
запрета напряжением в предоставленном протоколе не определён.

## Подтверждение команд и отключение

Подписка FFF1 выполняется до отправки пользовательских команд. В FFF2
пишутся **ровно два байта**, например `b'\x04\x01'`, а не строка `"0401"`.
Режим ATT-записи выбирается по свойствам FFF2: Write — с ответом,
Write Without Response — без ответа. ATT-ответ не является подтверждением
того, что плата начала/остановила измерения.

- START подтверждается только появлением кадров `03`.
- STOP подтверждается только событием `02 03 …`.
- Эхо `04 xx` не считается подтверждением выполнения.
- Через 3 с ожидания показывается сообщение об отсутствии подтверждения.
- Кабель/низкий заряд отменяют ещё не переданный START.
- START, поставленный в очередь и сразу отменённый STOP, не отправляется.

При нажатии «Отключить BLE» и закрытии окна приложение пытается отправить
STOP перед разрывом соединения. При обрыве радио, отключённом устройстве
или ошибке записи доставку/выполнение STOP гарантировать невозможно.
После автоматического переподключения требуется снова нажать START.

## Параметры PowerShell

```powershell
& "C:\Users\Oleg\Desktop\project\graph\start_ble_protocol.cmd"
& "C:\Users\Oleg\Desktop\project\graph\start_ble_protocol.cmd" --window 5
& "C:\Users\Oleg\Desktop\project\graph\start_ble_protocol.cmd" --name "E104-BT5032A" --notify-uuid fff1 --write-uuid fff2
```

При нескольких устройствах с одинаковым именем используйте `--address`
с адресом из списка в консоли. При повторяющихся UUID — `--service-uuid`.
При необходимости явно задайте `--write-mode response` или `no-response`;
выбранный режим обязан присутствовать в свойствах характеристики.

Проверка без устройства:

```powershell
& "C:\Users\Oleg\Desktop\project\graph\.venv_ble_adc\Scripts\python.exe" -m unittest discover -s "C:\Users\Oleg\Desktop\project\graph" -p "test_ble_protocol.py" -v
```
