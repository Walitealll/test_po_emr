# Кадр измерения

Скрипт разбирает поток платы по `docs/protocol.md`, а не сырые блоки по 80 байт.

Кадр `0x03` — 47 байт, little-endian: тип, 20 кодов ЭМГ от старого к новому, угол в десятых градуса (`1800` = 180°), метка времени в миллисекундах сетки 5 мс. Кадры `0x01` и `0x02` на том же потоке в график ЭМГ не попадают. Неизвестный байт выбрасывается, следующий кадр читается заново.

## Откуда байты

- `--port COM9` — последовательный порт, 115200. Это тот же вид входа, что у старого графика COM, но уже с кадрами.
- `--ble` — notify характеристики FFF1 модуля `E104-BT5032A`. Программа в FFF2 ничего не пишет. Пока с другого места не отправлен `START` (`04 01`), кадров `0x03` не будет.

Проверка разбора без платы:

```powershell
py -3 -m unittest discover -s test_po_emr -v
```

Запуск графика из этой папки:

```powershell
py -3 plot_frame.py --port COM9
py -3 plot_frame.py --ble
```
