# Кадр измерения

Скрипт разбирает поток платы по `docs/protocol.md`, а не сырые блоки по 80 байт.

Кадр `0x03` — 47 байт, little-endian: тип, 20 кодов ЭМГ от старого к новому, угол в десятых градуса (`1800` = 180°), метка времени в миллисекундах сетки 5 мс. Кадры `0x01` и `0x02` на график ЭМГ не попадают. Последний из каждого пишется под графиком: напряжение и байт зарядки, событие и код ошибки. Неизвестный байт выбрасывается, следующий кадр читается заново.

## Откуда байты

- Без флагов и `--port COM9` — COM9, 115200, 8N1, RTS выключен, DTR включён, без управления потоком. Другой порт задаётся `--port`.
- `--ble` — устройство `E104-BT5032A`, notify `fff1`, команды в `fff2`, поиск 6 с. Адрес вместо имени: `--address`. Если такой UUID есть в нескольких сервисах: `--service-uuid`.
- Кнопки на графике: «Старт» шлёт `04 01`, «Стоп» шлёт `04 02`. Сама программа измерение не начинает. «Подключить» и «Отключить» открывают и закрывают COM или BLE. Перед закрытием уходит «Стоп». Если устройство не найдено, поиск повторяется, пока связь не отключена кнопкой. Кабель и низкий заряд кнопку «Старт» не дают нажать.

Проверка разбора без платы:

```powershell
py -3 -m unittest discover -s test_po_emr -v
```

Запуск двойным щелчком. Первый раз скрипт сам создаёт `.venv` и ставит библиотеки, для этого нужен интернет.

- `start_frame.cmd` — COM9, 115200.
- `start_frame_ble.cmd` — BLE, устройство `E104-BT5032A`, notify `fff1`.

Другой порт или адрес можно дописать при запуске из PowerShell:

```powershell
.\start_frame.cmd --port COM9 --baud 115200
.\start_frame_ble.cmd --name E104-BT5032A --char-uuid fff1
```
