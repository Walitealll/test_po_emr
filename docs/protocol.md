# Протокол с телефоном

Двоичный кадр, little-endian. Плата → телефон: notify FFF1. Телефон → плата: write FFF2.

Преамбулы нет. Первый байт — тип. Длины тела в кадре нет: у каждого типа тело одного размера, по типу видно, сколько байт ещё забрать. Контрольной суммы в кадре нет, на приёме она не проверяется.

Неизвестный тип: первый байт отбрасывается, разбор продолжается со следующего. Несколько полных кадров в одном чтении разбираются подряд. Неполный кадр сохраняется и дополняется из следующего чтения.

## Контроль питания и зарядки, `0x01`

Плата → телефон, раз в 10 с, пока есть соединение. Тело 3 байта, кадр 4 байта. Процента заряда в кадре нет.


| Байт | Поле           | Тип    | Допустимо                                                            |
| ---- | -------------- | ------ | -------------------------------------------------------------------- |
| 0    | Тип            | uint8  | `0x01`                                                               |
| 1–2  | Напряжение АКБ | uint16 | милливольты                                                          |
| 3    | Зарядка        | uint8  | `0` кабель снят, `1` заряд идёт, `2` кабель подключён, заряд окончен |




## Контроль устройства (Device Control), `0x02`

Плата → телефон, в момент события. Тело 2 байта, кадр 3 байта.


| Байт | Поле       | Тип   | Допустимо    |
| ---- | ---------- | ----- | ------------ |
| 0    | Тип        | uint8 | `0x02`       |
| 1    | Событие    | uint8 | таблица ниже |
| 2    | Код ошибки | uint8 | справочник   |



| Событие | Смысл                                                                                 | Код ошибки       |
| ------- | ------------------------------------------------------------------------------------- | ---------------- |
| `1`     | Кабель вставлен, измерения запрещены                                                  | `0`              |
| `2`     | Принудительная остановка, низкий заряд. Уходит до разрыва, если телефон ещё подключён | `0`              |
| `3`     | Измерение остановлено, режим `CONNECTED`                                              | `0`, `1` или `2` |


Код ошибки нужен только для события `3`. Снятие кабеля отдельным событием не шлётся. Телефон видит его в байте зарядки следующего кадра `0x01`.


| Код ошибки | Смысл                                                  |
| ---------- | ------------------------------------------------------ |
| `0`        | Ошибки нет                                             |
| `1`        | BNO055 во время измерения сообщил ошибку, угол неверен |
| `2`        | BNO055 не ответил по I2C, таймаут                      |




## Контроль устройства (Device Control), `0x04`

Телефон → плата. Тело 1 байт, кадр 2 байта.


| Байт | Поле    | Тип   | Допустимо           |
| ---- | ------- | ----- | ------------------- |
| 0    | Тип     | uint8 | `0x04`              |
| 1    | Команда | uint8 | `1` START, `2` STOP |


`START` принимается только в `CONNECTED` и только без кабеля. Успех виден по потоку передачи измерений, отдельного ответа нет. `STOP` останавливает измерение. Любое другое число режим не меняет и ответа на телефон не получает.

## Передача измерений, `0x03`

Плата → телефон, 100 Гц, только пока идёт измерение. Окно кадра — 10 мс. ЭМГ за это окно снимается на 2 кГц, поэтому в кадре 20 отсчётов, от самого старого к самому новому. Угол один: он относится к концу окна, к самому новому отсчёту. Тело 46 байт, кадр 47 байт. Если отсчётов не 20 или угол к границе окна не готов, кадр не ставится. Хвост после остановки на телефон не ставится.


| Байт  | Поле            | Тип    | Допустимо                                                                                                                 |
| ----- | --------------- | ------ | ------------------------------------------------------------------------------------------------------------------------- |
| 0     | Тип             | uint8  | `0x03`                                                                                                                    |
| 1–40  | ЭМГ, 20 отсчётов | uint16 | сырой код АЦП, без знака, little-endian, шаг между отсчётами 0,5 мс                                                      |
| 41–42 | Угол            | uint16 | `0…1800`, шаг 0,1°                                                                                                        |
| 43–46 | Метка времени   | uint32 | миллисекунды монотонного счётчика, по `START` не сбрасывается. Шаг источника 5 мс, соседние кадры обычно отличаются на 10 |
